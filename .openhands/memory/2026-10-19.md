  DOES contain a copy of `.openhands/setup.sh`. So the reviewer's "404 on the
  per-conversation dir" mechanism is wrong for an attached workspace (the

create, re-probe `data.workspace.working_dir` (the assigned dir) and run there.

## 2026-10-19 (later still) — PR #18740 review fixes (commit 6e15c02)

Two of the three review points were real wiring gaps, both fixed:

1. First-message recovery unwired. `ConversationFirstMessageError` (thrown by
   `AgentServerConversationService.createConversation` when the withheld
   post-setup `sendEvent` fails) carried `conversationId`, but
   `useCreateConversation` let it propagate as a failed create -> the caller
   retried a NEW conversation, stranding the created one idle. Fix: catch it in
   the mutation, return a synthetic success `{conversation_id:
   error.conversationId, session_api_key: null, url: null}`, and enqueue the
   query as an ERRORED pending bubble on that id
   (`useOptimisticUserMessageStore`), so the existing retry affordance
   (`pending-user-messages.tsx` -> `useSendMessage`) resends to the SAME
   conversation. No consumer reads `url`/`session_api_key` from the mutation
   response, so the null shape is safe.
2. `onSetupScriptProgress` had no consumer. Plumbed through
   `CreateConversationVariables` -> `launchConversation` options -> service.
   Consumer: home launcher relabels its create toast
   (`toast.loading(..., {id})`) to `STATUS$SETTING_UP_WORKSPACE` while
   `phase === "running"`, back to `HOME$CREATING_CONVERSATION` otherwise. Key
   already existed in all 16 locales.
3. Third point was the `new_worktree` wrong-dir concern -> already fixed in
   3ea2558.

Gotchas hit:
- The recovery lives INSIDE `useCreateConversation.mutationFn`, not the service,
  because the mutation is the layer that knows the caller's `query` text (the
  service sends `payload.initial_message`, not the raw query).
- Adding an await inside a test that triggers navigation leaks an async tail
  into the NEXT test (shared `mockNavigate` gets cleared in beforeEach, then the
  late navigate fires). Always `await waitFor(navigate)` at the end of such
  tests.
- `SetupScriptStatusUpdate` is NOT re-exported from
  `agent-server-conversation-service.api`; import the type from
  `#/api/setup-script-service`.
- Test file `use-create-conversation.test.tsx` has PRE-EXISTING lint errors
  (unused `beforeEach`, `AGENT_PROFILES_QUERY_KEYS`); not mine.
