Warning text should follow the theme.

Six hardcoded yellow and amber findings cross four UI paths. This proposal gives warning text its own semantic role, readable on every built-in theme while keeping control-warning color behavior separate.

Base: 738b23d2 · implementation: cca69c13 · spec WN-001

Watch Before / After Download MP4 Issue #18331

Change

One warning role, two kinds of color ownership

Before · palette utility

Text and icons pick fixed yellow or amber shades. Light themes wash them out, and host overrides cannot reach those classes.

text-amber-300
text-yellow-400
border-amber-400/30
bg-amber-400/5
→

After · semantic roles

Small warning text uses feedback-warning. The trust notice keeps the existing warning role for its tint and border.

text-feedback-warning
border-warning/30
bg-warning/5

The role is added to AGENT_SERVER_UI_DEFAULT_CSS_VARIABLES, so an embedding application can supply its own value through the existing CSS-variable override path. No server API or compatibility change is needed.

Base and dark themes

--oh-feedback-warning: #c9b974. Dark themes inherit the default value; the separate control role remains untouched.

Light palettes

Light+ uses #7D5D08; Solarized Light uses #735400. Both keep small text above 4.5:1 on the tested warning surfaces.
