MCP Apps in Agent Canvas,
opt in at the presentation layer

A trusted embedding can associate an MCP result with a ui:// resource and render an interactive, isolated App beside the existing tool text. The change adds frontend contracts, rendering, an official protocol bridge, live locale adaptation, and a local fixture.

1The default Canvas keeps its existing behavior

This is an opt-in frontend prototype. Agent Server/client 1.54.0 has no production adapter in this increment. A caller must explicitly provide a Host, a conversation scope, and an event-ID-keyed presentation sidecar; otherwise the existing MCP text path remains active.

8Production work remains explicit

  1. Published server/client contracts: preserve tool-definition UI metadata, private result metadata, and originating server provenance; provide conversation-bound resource/tool proxies.
  2. Production authorization: enforce tool visibility, user confirmation, audit, and rate limits before the Host exposes write callbacks.
  3. Context and history: consume App context in the next model turn and define Cloud history persistence without mixing private View metadata into canonical transcripts.
  4. Install modes and ACP: choose dedicated sandbox deployment for each installation path and add ACP provenance/resource routing before supporting ACP Apps.
