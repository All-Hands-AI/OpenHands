OPENHANDS · REVIEW DESIGN

Finish test scheduling before publishing CI markers.

Retries are extra attempts, not extra test cases. The reporter now saves progress after each attempt and publishes the final verdict from a global teardown hook, after retries finish and before web-server cleanup can hang.

★ A complete passing run can still use CI's teardown grace. A truncated run, unexpected test result, or runner error cannot create a passing marker.

tests/e2e/mock-llm/reporters/done-marker-reporter.ts:43 · tests/e2e/mock-llm/reporters/done-marker-teardown.ts:1

1. Completion belongs to the scheduler

The current main reporter counts onTestEnd calls. A serial group can report passed and skipped cases before rerunning all of them, so neither attempt counts nor the first result for every case establish completion.

tests/e2e/mock-llm/reporters/done-marker-reporter.ts:58

The changed edge is the explicit globalTeardown → finishTestRun() signal. The existing workflow polling interface stays the same. tests/e2e/mock-llm/reporters/done-marker-teardown.ts:1 · playwright.mock-llm-docker.config.ts:152

2. A passing marker has strict conditions

The latest result replaces the previous attempt for the same test ID. Finalization checks every declared case, expected outcomes, and global errors. A later error removes a stale passing marker. Only a web-server plugin teardown timeout after a confirmed complete pass preserves the existing rescue.
