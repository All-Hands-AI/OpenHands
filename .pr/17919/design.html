Agent Canvas · maintenance proposal · 2026-10-13

Delete the whole conversation set on the confirmed backend

Delete all now loads every page before enabling confirmation. Confirmation snapshots the complete ID set and one typed deletion scope, so asynchronous callbacks or planning-child lookups cannot redirect later requests to a different backend or organization.

★ With 23 real blank conversations, the baseline confirms 20 and leaves 3. This proposal confirms 23 and leaves 0 in two desktop and two phone runs. The destructive operation remains bound to its confirmed transport.

Functional revision 5a6bddcb3b55 compared with bdb69754a113. This temporary review page and its images are documentation only; the repository’s same-repository approval workflow removes .pr/.

Every page is ready before Confirm becomes available

The existing paginated query remains the data owner. Preparation tracks visited cursors, blocks confirmation after a later-page error, and discards a canceled or superseded request. Bulk Confirm supplies it before mutateAsync; optional single-delete callers keep their existing call shape. +# Conversation deletion
+
+### CD-001: Bulk deletion enumerates its complete scope
+
+- Delete all loads every backend page and deduplicates conversation IDs before enabling confirmation.
+- The confirmation count includes hidden archived conversations.
+- A failed later page blocks deletion; cancellation discards late preparation responses.
+
+### CD-002: Confirmed deletion captures its transport
+
+- Bulk confirmation captures one typed backend client before asynchronous mutation callbacks.
+- Local planning-child lookups and all deletes use that captured client.
+- Cloud deletes preserve the captured backend and organization; suspension belongs to that original organization.
